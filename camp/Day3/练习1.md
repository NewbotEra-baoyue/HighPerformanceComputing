# MPI 环形通信基准测试

基于 OpenMPI 的两个小程序：MPI 版 Hello World 入门示例，以及环形（Ring）通信延迟/带宽基准测试。

## 文件说明

tools/distributed文件夹下

| 文件 | 说明 |
| --- | --- |
| `hello_mpi.c` | MPI Hello World，每个进程打印 rank、总进程数和主机名 |
| `ring_benchmark.c` | 环形通信基准测试，扫描 1 B ~ 1 MB 消息，输出每跳延迟与带宽 |


## 环境要求

- OpenMPI（提供 `mpicc`、`mpirun`）
- GCC

```bash
sudo apt install openmpi-bin libopenmpi-dev
```

## 编译

```bash
mpicc -O2 -Wall -o hello_mpi hello_mpi.c
mpicc -O2 -Wall -o ring_benchmark ring_benchmark.c
```

## 运行

### Hello World（本地 4 进程）

```bash
mpirun --allow-run-as-root -np 4 ./hello_mpi
```

`--allow-run-as-root` 仅在以 root 身份运行时需要，普通用户可省略。

### 环形通信测试（本地 4 / 8 进程）

```bash
mpirun --allow-run-as-root --mca btl self,vader -np 4 ./ring_benchmark
mpirun --allow-run-as-root --mca btl self,vader -np 8 ./ring_benchmark
```

`--mca btl self,vader` 强制走共享内存（vader）通道，用于屏蔽本机 TCP 网卡扫描产生的警告噪声；不加也能正常运行。

## 原理

构造逻辑环：rank `i` 只与右邻居 `(i+1)%size` 发送、与左邻居 `(i-1+size)%size` 接收（`MPI_Sendrecv`，天然无死锁）。消息每绕环一圈经过 `size` 跳，因此：

```
每跳耗时 = 总耗时 / 迭代次数 / 进程数
带宽     = 消息字节数 / 每跳耗时
```

消息大小从 1 B 按倍数扫描到 1 MB，小消息迭代 1 万次、大消息 500 次，每档先做一轮 warm-up。

## 输出解读

```
# ring benchmark over 4 processes
# bytes | per-hop us | per-hop us (avg) | bandwidth MB/s
       1 |      0.064 |          0.064 |        15.55
     ...
  524288 |      6.225 |          6.228 |     84182.14
```

- **延迟**：看 1 B 小消息档的每跳耗时，本机共享内存约为 0.05~0.1 µs。
- **带宽**：看大消息档，随消息增大趋于稳定；本机 4 进程实测峰值约 84 GB/s，8 进程约 170 GB/s。

注意：本地多进程走的是**共享内存**而非网络，测出的是内存拷贝级别的带宽，不代表网络性能。

## 多节点运行（真实网络）

代码无需修改，准备一个 hostfile：

```
node1 slots=4
node2 slots=4
```

确保节点间 ssh 免密、MPI 版本一致，然后：

```bash
mpirun --hostfile hosts -np 8 ./ring_benchmark
```

此时 rank 分布在不同物理机，消息走 TCP 或 InfiniBand，测得的才是网络环形通信的真实延迟（微秒级）与带宽（GB/s 量级）。

## 结果解读：
### 1. 小消息区（1 B ~ 2 KB）：延迟主导，带宽数字无意义
每跳耗时在 0.055~0.2 µs 之间抖动。
抖动（64 B 突然跳到 0.195 µs）是小消息本身耗时太短，被 OS 调度、缓存等噪声淹没的正常现象。
结论：延迟 ≈ 0.06 µs/跳，性能很好。

### 2. 中消息区（16 ~ 512 KB）：带宽主导，线性区
每跳耗时随消息大小近似线性增长（16 KB→1.3 µs，512 KB→15.4 µs），这正是带宽受限的表现。这段的斜率就是真实带宽：

### 3. 大消息区（ MB)：异常回落
1 MB 档每跳耗时跳到 62 µs，带宽从 34 GB/s 跌回 16.9 GB/s。这种"大消息反而变慢"一般不是通信本身的问题，常见原因是：
内存带宽竞争加剧；
内存不在同一个节点上；
大消息的拷贝机制排查。
