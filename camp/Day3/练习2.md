# 用 MPI 实现并行归并排序，多节点测试可扩展性

使用 MPI 实现的并行归并排序,并测试其可扩展性。

## 文件结构

tools/distributed文件夹下

| 文件 | 说明 |
|------|------|
| `mergesort_mpi.c` | 并行归并排序主程序 |

## 算法

经典三阶段:

1. **分发**:rank 0 生成全局数组(种子固定为 42),计算各进程分量(`counts`/`displs`,前 `N % size` 个进程多分一个元素),`MPI_Scatterv` 均分。
2. **局部排序**:每个进程对本地段串行排序(`qsort`)。
3. **归并树**:第 `step = 1, 2, 4, …` 轮中,`rank % (2·step) == step` 的进程把整段有序数据发给低邻居;`rank % (2·step) == 0` 且邻居存在的进程接收并二路归并。任意进程数(含非 2 的幂)均正确,例如 7 个进程:第 1 轮 (1→0, 3→2, 5→4),第 2 轮 (2→0, 4→...)。

结束后 rank 0 持有全局有序数组,校验**有序性**与**校验和**。

## 编译与运行

```bash
mpicc -O3 -march=native -o mergesort_mpi mergesort_mpi.c
mpirun -np 4 ./mergesort_mpi
```
-np参数为节点数，调整节点数，测试


## 结果

| np | 总时间 (s) | 加速比 | 并行效率 |
|----|-----------|--------|---------|
| 1  | 16.55 | 1.00 | 100%  |
| 2  | 9.52  | 1.74 | 86.8% |
| 4  | 6.53  | 2.53 | 63.3% |
| 8  | 4.71  | 3.52 | 43.9% |
| 16 | 5.33  | 3.11 | 19.4% |
| 28 | 5.73  | 2.89 | 10.3% |

## 分析

np = 8 达到最佳加速比 3.5x。
np = 28 时效率反而下降:内存带宽饱和,且通信占比随进程数增大。
