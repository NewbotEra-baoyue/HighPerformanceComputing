# 使用roofline计算所选系统的实际性能

## 环境
sudo apt-get install gcc g++ openmpi-bin libopenmpi-dev gnuplot

## 工具
git clone https://github.com/NewbotEra-baoyue/HighPerformanceComputing.git
cd HighPerformanceComputing/tool/roofline

## roofline

### 测试性能
cd Empirical_Roofline_Tool-1.1.0
./ert Config/config.mycpu.01

### Result.MyCPU文件夹会输出如下结果
#### 编译不同 FLOP 强度（1, 2, 4, 8, 16 FLOP/迭代）的微内核
#### 在不同线程数/进程数下运行
#### 测量各级缓存（L1, L2, L3）和 DRAM 的带宽
#### 测量 FP64 浮点峰值
#### 生成 Roofline 数据文件和图表

| ERT 测量项                    | 物理意义                               | 工程价值                                                        |
| -------------------------- | ---------------------------------- | ----------------------------------------------------------- |
| **不同 FLOP 强度（1,2,4,8,16）** | 改变运算强度（FLOP/Byte），覆盖从内存受限到计算受限的全谱系 | 生成 Roofline 图上的斜线部分，确定"转折点"（运算强度多大时从内存瓶颈转为计算瓶颈）             |
| **不同线程数（1,2,4,8,16...）**   | 测量并行扩展性和多核内存竞争                     | 找到最佳线程配置；线程过多时内存带宽饱和，性能不再线性增长                               |
| **L1/L2/L3/DRAM 带宽**       | 不同存储层级的数据供给能力                      | 每一层都是一道独立的"带宽天花板"。小数据量在 L1 内达到 TB/s 级，大数据量落到 DRAM 只有几十 GB/s |
| **FP64 浮点峰值**              | CPU/GPU 的纯计算上限                     | 水平天花板。若应用运算强度足够高，性能上限就是这个值                                  |
| **Roofline 图表**            | 可视化所有天花板                           | 把应用的实际性能点（通过其他工具测量）叠加到图上，一眼看出是**内存瓶颈**还是**计算瓶颈**            |
