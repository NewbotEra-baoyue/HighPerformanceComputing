# 编写一个 CUDA Kernel，实现向量加法

两个GPU 向量加法实现，手写CUDA Kernel与调用库

## 环境

- GPU: NVIDIA GeForce RTX 自己的硬件
- CUDA Toolkit: 对应硬件的软件版本
- 驱动: 对应硬件的软件版本（注意wsl用户，驱动要安装在windows）

## 文件说明

tools/gpu文件夹下

| 文件 | 说明 |
|---|---|
| `vec_add_kernel.cu` | 手写 CUDA Kernel 
| `vec_add.cu` | 调用库版本

## 编译与运行

nvcc 不在默认 PATH 中，位于 `/usr/local/cuda/bin/nvcc`。

```bash
# kernel 版本
nvcc -O2 -arch=sm_89 -o vec_add_kernel vec_add_kernel.cu
./vec_add_kernel

# Thrust 版本
nvcc -O2 -arch=sm_89 -o vec_add vec_add.cu
./vec_add
```

## 性能对比

N = 1,048,576（约 104 万 float），各取 100 次平均（已热身）：

| 项目 | 耗时 |
|---|---|
| CPU 串行加法 | 0.234 ms |
| GPU Thrust 加法（不含数据传输） | 0.032 ms |
| Host→Device 拷贝 4 MB | 0.345 ms |
| GPU 相对 CPU 加速比 | 约 7.4x |

结论：

- 两种 GPU 实现计算性能相当——Thrust 底层生成的也是元素级并行 kernel，该规模下瓶颈在显存带宽（实测约 393 GB/s），不在实现方式
- 数据拷贝比计算慢一个数量级。小数组或单次调用不值得上 GPU；数据已在显存上、或数组足够大（计算/传输比高）时才有收益
- 手写 kernel 灵活（grid-stride、操作融合、自定义访存模式），Thrust 适合标准算法、代码极简

## 关于计时热身

首次调用 GPU 会触发 CUDA 上下文初始化、内核模块加载、GPU 升频等一次性开销（本机 WSL 环境下首次数据拷贝可达 195 ms）。直接测首轮得到的是初始化时间而非计算时间。正确做法：

1. 计时前用**同一路径、同样数据**先跑一遍
2. 热身后必须 `cudaDeviceSynchronize()`（或依赖 `cudaMemcpy` 的隐式同步），确保初始化真正完成
3. 正式计时跑多轮（如 100 次）取平均

示例见 `vec_add_no_kernel.cu`。
