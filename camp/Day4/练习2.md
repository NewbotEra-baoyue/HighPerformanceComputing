# 用 CUDA 实现一个图像卷积程序，尝试达到峰值算力 30%

CUDA 实现 2D 图像卷积基准程序
针对 15×15 卷积核 在 8192×8192 单精度浮点图像 上的性能优化

## 文件说明

tools/gpu文件夹下

| 文件 | 说明 |
| --- | --- |
| `conv.cu` | 优化 kernel + 朴素参考 kernel + 基准与校验 |

## 编译运行

```bash
nvcc -arch=sm_89 -O3 --use_fast_math -o conv conv.cu
./conv
```

输出示例：

```
image: 8192x8192, kernel: 15x15
time:  1.851 ms/iter (20 iters)
perf:  16.31 TFLOPS  (FP32 peak 29.15 TFLOPS)  ->  56.0% of peak
check: max abs err = 0.000e+00  PASS
```

## 问题设定

- 输入：8192×8192 单通道 float 图像（随机值）
- 卷积核：15×15（随机值，zero-padding）
- 性能口径：CUDA events 计时 20 次取平均，统计 FLOPs = 2·H·W·K²
- 正确性：与朴素参考 kernel（每线程 1 个输出，直接读全局内存）逐点对比，max abs err < 1e-3

## 优化方法

### 为什么选 15×15 卷积核（roofline 分析）

要达到峰值算力 30%，计算强度需 > 0.3 × (29200 GFLOPS / 504 GB/s) ≈ 17 FLOP/byte。
单通道卷积的计算强度 ≈ K²/4，因此需要 K ≥ 9×9。取 15×15 时，计算时间（~1ms）
与最小显存流量时间（~1ms）几乎相等，正好位于 roofline 交叉点，效率上限最高。

### Kernel 优化（`conv_opt`）

1. **卷积核放 constant memory**（15×15×4B = 900B）：每 tap 一次广播读取，不占寄存器
2. **shared memory 平铺**：每个 256 线程 block 计算 64×64 输出 tile，把 78×78 输入
   （含 7 像素 halo）载入 SMEM（~24KB），边界越界补零，内部与边界 block 走同一
   无分支代码路径
3. **4×4 register blocking**：每线程算 4×4 共 16 个输出，16 个输入窗口值驻留寄存器
   并沿 kx 滑动——每个 tap 每行只新增 1 次 SMEM 读取，SMEM 加载 : FMA = 1 : 3.3，
   消除共享内存带宽瓶颈
4. **float4 向量化写回**：每线程一次写 16 字节，warp 内 512B 完全合并
5. **全循环展开**：`#pragma unroll` 展开 15×15 内层循环，调度器可充分双发射 FMA
